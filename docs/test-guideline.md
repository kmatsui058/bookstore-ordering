# テストガイドライン

このドキュメントは[ドキュメント作成ガイドライン](../contracts/docs/guides/documentation.md)に準拠する必要があります。

このリポジトリのテストを書き・レビューするときに従うものです。

## 位置づけ

テストは、仕様（`openspec/specs/`）の振る舞いを動く形で残すものです。テストの名前がそのまま仕様の文になるように書きます。

## 守ること

- テストを先に書いてから実装する（失敗するテスト → 通す最小の実装 → リファクタリング）
- 同じ処理に対するケースが2件以上あれば、テーブル駆動で書く。`t.Run` を並べない
- ケースの名前は日本語で「Given: …, When: …, Then: …」と書く
- ドメイン層のテストは、すべての不変条件と状態の遷移（できる遷移とできない遷移）を確かめる。できないときは、状態もイベントも変わらないことまで確かめる
- テストのための値は、コマンドを実行して作る。集約にテストのためのセッターを足さない
- アプリケーション層のテストは、依存をモック（`go.uber.org/mock` で生成したもの）かメモリのリポジトリに置き換え、何をどの順で保存・公開するかを確かめる
- ドメインの列挙型の値が、契約（OpenAPI の定義）の値と一致することをテストで確かめる
- 内部の実装ではなく、外から見える振る舞いを確かめる

## 実行

- `task test` ですべてのテストを実行する
