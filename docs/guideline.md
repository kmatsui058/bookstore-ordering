# 実装ガイドライン

このドキュメントは[ドキュメント作成ガイドライン](../contracts/docs/guides/documentation.md)に準拠する必要があります。

このリポジトリの Go のコードを書き・レビューするときに従うものです。「守ること」は必ず守り、それ以外は指針として扱ってください。

## 位置づけ

業務のルールと語の正本は、契約リポジトリ（サブモジュール `contracts`）の LikeC4 のモデルです。コードはモデルに従い、モデルにない語や振る舞いを足しません。API の形の正本は、契約リポジトリの OpenAPI の定義です。

## 層の責務

- ドメイン層（`internal/modules/<モジュール>/domain`、`internal/shared/domain`）: 集約・値オブジェクト・ドメインイベントで、不変条件と状態の遷移を守る。永続化・外部への伝送・HTTP を知らない
- アプリケーション層（`app/command`・`app/query`）: ユースケースごとに、読み込み・コマンドの実行・永続化を1つのトランザクションにまとめる。イベントの公開はコミットのあとに行う
- インフラ層（`infra`）: アプリケーション層が要求するインターフェースを実装する
- プレゼンテーション層（`internal/presentation`）: リクエストをドメインの型に変換してユースケースを呼び、結果とエラーをレスポンスに変換する。業務のルールを持たない

## 守ること

- 型・関数・メソッド・パッケージには GoDoc で責務を書く。モデルの要素に対応するものは、和名と LikeC4 のビュー ID を書く
- コードの中のコメントは `// TODO:` と `// FIXME:` だけにする。説明が要るなら、名前を直すか、テストの名前で表す
- change の設計の番号（D1 など）をコードに書かない。archive したあと辿れなくなる
- 英名はモデルの `summary` に合わせる
- インターフェースは使う側のパッケージで定義し、使うメソッドだけを持たせる。引数はインターフェースで受け、戻り値は構造体で返す
- 集約の状態は、イベントを当てはめることでだけ変える。テストのためのセッターや、発行したイベントを消すメソッドを足さない
- 集約はバージョンを持ち、同じバージョンのイベントを保存しようとしたら衝突として拒む（楽観的並行性制御）
- 列挙型の値を switch するところは、すべての値を case に書く（`exhaustive` で検査する）。すべての値を返す関数（`AllXxx`）を用意する
- 生成物（`internal/presentation/api/gen/`・`mock_*/`）を手で直さない。直すときは契約の定義かインターフェースを変えて生成し直す
- 要求されていない機能を先回りして作らない（YAGNI）
